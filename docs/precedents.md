# Описание прецедентов для приложения RepairShopManager

## Прецедент 1: Регистрация мастера

| Раздел | Описание |
|--------|----------|
| **Краткое описание** | Новый сотрудник регистрируется в системе, используя код доступа, предоставленный администратором мастерской. |
| **Субъекты** | Новый сотрудник (Мастер), Мобильное приложение. |
| **Предусловия** | Приложение установлено на устройстве Android. Администратор предоставил код доступа сотруднику. |
| **Основной поток** | 1. Сотрудник запускает приложение и переходит на экран регистрации.<br>2. Система отображает форму регистрации с полями: ФИО, Email, Телефон, Пароль, Код доступа.<br>3. Сотрудник с клавиатуры заполняет все обязательные поля.<br>4. Система проверяет корректность введенных данных (формат email, длину пароля).<br>5. Сотрудник нажимает кнопку «Зарегистрироваться».<br>6. Система проверяет код доступа в Firebase Firestore (коллекция settings/registration).<br>7. При совпадении кода система создает учетную запись в Firebase Authentication и добавляет документ в коллекцию users с ролью «master».<br>8. Система автоматически авторизует пользователя и перенаправляет на главный экран приложения. |
| **Альтернативный поток** | 1. **Неверный код доступа:**<br>   Введенный код не совпадает с кодом в базе. Система выводит сообщение «Неверный код доступа» и блокирует регистрацию.<br><br>2. **Email уже зарегистрирован:**<br>   Пользователь с таким email уже существует. Система выводит сообщение «Пользователь с таким email уже зарегистрирован» и предлагает войти.<br><br>3. **Отмена:**<br>   Сотрудник нажимает кнопку «Назад», форма закрывается, возврат на экран входа. |
| **Постусловия** | В Firebase создана учетная запись нового мастера с базовыми правами доступа. Мастер авторизован и может работать с системой. |

## Прецедент 2: Авторизация в системе

| Раздел | Описание |
|--------|----------|
| **Краткое описание** | Зарегистрированный сотрудник входит в систему, используя свои учетные данные. |
| **Субъекты** | Сотрудник мастерской (Мастер/Администратор), Мобильное приложение. |
| **Предусловия** | Сотрудник ранее зарегистрирован в системе. Приложение запущено на устройстве. |
| **Основной поток** | 1. Сотрудник открывает приложение.<br>2. Система отображает экран входа с полями Email и Пароль.<br>3. Сотрудник вводит свои учетные данные с клавиатуры.<br>4. Сотрудник нажимает кнопку «Войти».<br>5. Система отправляет запрос в Firebase Authentication.<br>6. При успешной авторизации система загружает данные пользователя из Firestore.<br>7. Система определяет роль пользователя (master или admin).<br>8. Система перенаправляет пользователя на главный экран с соответствующими правами доступа. |
| **Альтернативный поток** | 1. **Неверные учетные данные:**<br>   Email или пароль введены неправильно. Система выводит сообщение «Неверный email или пароль».<br><br> |
| **Постусловия** | Сотрудник авторизован в системе и получает доступ к функционалу в соответствии со своей ролью. |

## Прецедент 3: Создание нового заказа на ремонт

| Раздел | Описание |
|--------|----------|
| **Краткое описание** | Мастер принимает устройство от клиента, проводит диагностику и создает заказ на ремонт с указанием неисправности, необходимых услуг и запчастей. |
| **Субъекты** | Мастер, Мобильное приложение. |
| **Предусловия** | Мастер авторизован в системе. Открыта вкладка «Заказы». В справочниках есть услуги и запчасти. |
| **Основной поток** | 1. Мастер нажимает кнопку «Создать заказ».<br>2. Система открывает форму создания заказа.<br>3. Мастер заполняет обязательные поля: Модель устройства, Имя клиента, Телефон клиента, Описание неисправности.<br>4. Мастер добавляет необходимые услуги из прайс-листа, выбирая их из списка.<br>5. Мастер добавляет необходимые запчасти из склада, указывая количество.<br>6. При добавлении каждой запчасти система проверяет наличие на складе.<br>7. Если запчасть в наличии, система резервирует её и уменьшает количество на складе.<br>8. Система автоматически рассчитывает и отображает общую стоимость (сумма услуг + запчастей).<br>9. Мастер нажимает кнопку «Сохранить».<br>10. Система создает карточку, статусом «Новый», привязкой к текущему мастеру и текущей датой создания.<br>11. Новый заказ появляется в списке заказов. |
| **Альтернативный поток** | 1. **Недостаточно запчастей на складе:**<br>   Система блокирует добавление запчасти и выводит сообщение «Недостаточно товара на складе. Доступно: X шт.».<br><br>2. **Не заполнены обязательные поля:**<br>   Система подсвечивает незаполненные поля и выводит сообщение «Заполните все обязательные поля».<br><br>3. **Отмена создания:**<br>   Мастер нажимает кнопку «Назад» или «Отмена». Система возвращает зарезервированные запчасти на склад и закрывает форму без сохранения.<br><br>4. **Клиент отказался от ремонта:**<br>   Мастер создает заказ со статусом «Отменен» для ведения статистики обращений. |
| **Постусловия** | В базе данных создан новый заказ со статусом «Новый». Запчасти списаны со склада. Заказ готов к переводу в работу. |

## Прецедент 4: Выдача устройства клиенту

| Раздел | Описание |
|--------|----------|
| **Краткое описание** | Мастер выдает отремонтированное устройство клиенту и закрывает заказ. |
| **Субъекты** | Мастер, Клиент, Мобильное приложение. |
| **Предусловия** | Существует заказ со статусом «Готов». Клиент прибыл за устройством. |
| **Основной поток** | 1. Мастер открывает вкладку «Заказы» и фильтрует по статусу «Готов».<br>2. Мастер находит заказ по имени клиента или номеру телефона.<br>3. Мастер тапает по заказу для просмотра деталей.<br>4. Система отображает полную информацию о заказе и итоговую стоимость.<br>5. Мастер информирует клиента о стоимости ремонта.<br>6. Клиент оплачивает услуги (наличными или картой).<br>7. Мастер нажимает кнопку «Выдано».<br>8. Система запрашивает подтверждение действия.<br>9. Система изменяет статус заказа на «Выдан» и обновляет дату завершения.<br>10. Заказ перемещается в историю. |
| **Альтернативный поток** | <br>1. **Клиент не забрал устройство:**<br>   Заказ остается в статусе «Готов» до получения клиентом.<br><br>3. **Отмена:**<br>   Мастер нажимает «Отмена» в диалоге подтверждения, статус не изменяется. |
| **Постусловия** | Заказ закрыт со статусом «Выдан». Информация сохранена в истории для возможных гарантийных обращений. |

## Прецедент 5: Управление складом запчастей

| Раздел | Описание |
|--------|----------|
| **Краткое описание** | Администратор или мастер добавляет новые запчасти на склад, редактирует информацию о существующих позициях и отслеживает остатки. |
| **Субъекты** | Администратор/Мастер, Мобильное приложение. |
| **Предусловия** | Пользователь авторизован в системе. Открыта вкладка «Склад». |
| **Основной поток** | 1. Пользователь нажимает кнопку «Добавить запчасть».<br>2. Система открывает форму добавления запчасти.<br>3. Пользователь заполняет поля: Артикул, Название, Количество, Цена.<br>4. Система проверяет уникальность артикула.<br>5. Пользователь нажимает кнопку «Сохранить».<br>6. Новая запчасть появляется в списке склада. |
| **Альтернативный поток** | 1. **Редактирование запчасти (только Администратор):**<br>   Администратор тапает по запчасти, изменяет данные (название, цену), система обновляет цену<br>2. **Пополнение склада:**<br>   Пользователь находит запчасть, нажимает «Пополнить», вводит количество. Система увеличивает текущее количество на указанное значение.<br><br>3. **Дубликат артикула:**<br>   Запчасть с таким артикулом уже существует. Система выводит сообщение «Артикул уже используется» и предлагает изменить или перейти к существующей записи.<br><br>4. **Удаление запчасти (только Администратор):**<br>   Администратор выбирает запчасть и нажимает «Удалить». Удаляется документ.<br><br>5. **Поиск запчасти:**<br>   Пользователь использует строку поиска для фильтрации по артикулу или названию. |
| **Постусловия** | Склад обновлен. Данные о запчастях актуальны и доступны для использования в заказах. |

## Прецедент 6: Управление прайс-листом услуг

| Раздел | Описание |
|--------|----------|
| **Краткое описание** | Администратор добавляет, редактирует и удаляет услуги в прайс-листе мастерской. |
| **Субъекты** | Администратор, Мобильное приложение. |
| **Предусловия** | Администратор авторизован в системе. Открыта вкладка «Услуги». |
| **Основной поток** | 1. Администратор нажимает кнопку «Добавить услугу».<br>2. Система открывает форму добавления услуги.<br>3. Администратор заполняет поля: Название услуги, Стоимость.<br>4. Администратор нажимает кнопку «Сохранить».<br>5. Новая услуга появляется в прайс-листе и становится доступна для выбора при создании заказов. |
| **Альтернативный поток** | 1. **Редактирование услуги:**<br>   Администратор тапает по услуге, изменяет название или цену.<br><br>2. **Удаление услуги:**<br>   Администратор выбирает услугу и нажимает «Удалить». Система запрашивает подтверждение и удаляет. Услуга перестает отображаться в прайс-листе.<br><br>3. **Неполные данные:**<br>   Администратор не заполнил обязательные поля. Система подсвечивает их и блокирует сохранение.<br><br>4. **Отмена:**<br>   Администратор нажимает «Назад», форма закрывается без сохранения. |
| **Постусловия** | Прайс-лист обновлен. Изменения сразу доступны всем мастерам при создании заказов. |

## Прецедент 7: Управление персоналом (для Администратора)

| Раздел | Описание |
|--------|----------|
| **Краткое описание** | Администратор просматривает список сотрудников, изменяет код доступа для регистрации новых мастеров и удаляет учетные записи уволенных сотрудников. |
| **Субъекты** | Администратор, Мобильное приложение. |
| **Предусловия** | Администратор авторизован в системе со статусом admin. Открыта вкладка «Персонал». |
| **Основной поток** | 1. Администратор открывает вкладку «Персонал».<br>2. Система загружает и отображает список всех зарегистрированных сотрудников.<br>3. При необходимости администратор может удалить сотрудника, нажав соответствующую кнопку.<br>4. После подтверждения система удаляет сотрудника |
| **Альтернативный поток** | 1. **Изменение кода доступа:**<br>   Администратор нажимает кнопку «Изменить код доступа». Система открывает диалог ввода нового кода. Администратор вводит новый код и подтверждает.<br>2. **Просмотр кода доступа:**<br>   Администратор нажимает кнопку «Показать код доступа». Система отображает текущий код для передачи новым сотрудникам.<br><br>3. **Фильтрация по роли:**<br>   Администратор может отфильтровать список, показывая только мастеров или только администраторов. |
| **Постусловия** | Список персонала актуален. Уволенные сотрудники удалены. Новый код доступа вступил в силу для следующих регистраций. |
