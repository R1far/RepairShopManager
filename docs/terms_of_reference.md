# ТЕХНИЧЕСКОЕ ЗАДАНИЕ 

### 1. Цели разработки
Основной целью проекта является создание автоматизированной системы для учета деятельности сервисного центра. Внедрение приложения направлено на решение следующих задач:

* **Оптимизация** процесса регистрации и отслеживания статусов заказов.
* **Обеспечение** прозрачного учета складских остатков и используемых запчастей.
* **Минимизация ошибок** при расчете стоимости услуг за счет использования единого прайс-листа.
* **Централизованное хранение** истории ремонтов для оперативного доступа к данным.

### 2. Описание системы
Приложение представляет собой решение на базе Android для комплексного управления мастерской. Система объединяет в себе функции CRM-системы и складского учета.

**Основные модули системы:**
* **Учет заказов:** регистрация обращений, выбор услуг из справочника и мониторинг этапов ремонта.
* **Складской модуль:** ведение базы запчастей с автоматическим списанием и привязкой к конкретному заказу.
* **Модуль администрирования:** управление правами доступа, корректировка ценовой политики и работа с архивом выполненных работ.

### 3. Целевая аудитория
Программный продукт ориентирован на сотрудников малых мастерских по ремонту цифровой техники:

* **Мастера-приемщики:** используют приложение для первичной регистрации клиентов и выдачи устройств.
* **Технические специалисты:** используют систему для фиксации хода работ и списания необходимых деталей.
* **Руководители (Администраторы):** осуществляют контроль за деятельностью персонала, управляют прайс-листом и анализируют архив заказов.

### 4. Общие требования
Для обеспечения стабильной работы и безопасности данных к приложению предъявляются следующие требования:

* **Технологический стек:** разработка должна быть выполнена на языке **Java** для платформы Android с использованием облачной базы данных **Firebase Firestore**.
* **Требования к доступу:** доступ к функциям системы должен предоставляться только авторизованным пользователям. Регистрация новых учетных записей ограничивается мастер-паролем (кодом доступа).
* **Интерфейс и юзабилити:** графическая оболочка должна быть интуитивно понятной, обеспечивать быстрое взаимодействие с элементами списков и соответствовать современным стандартам мобильной разработки.
